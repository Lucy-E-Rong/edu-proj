# Teacher Pipeline

This project separates teacher-stage customization into four layers:

1. `original/`
   - teacher-provided source files
   - kept unchanged
2. `extracted/`
   - normalized text blocks extracted from source files
   - generated by deterministic parsing and file extraction
3. `processed/`
   - teacher-stage supervised fine-tuning JSONL
   - generated from extracted blocks
4. `validated/`
   - validation step that checks JSONL schema and basic content quality

## Why this design

- Teacher materials are heterogeneous.
- Raw files should remain untouched for auditability.
- Deterministic extraction is more reliable than using a model to recover source
  text from PDFs or Markdown.
- Model-assisted generation is more suitable at the stage where extracted text
  is transformed into teacher-stage supervision.

## Scripts

Extract source files into normalized blocks:

```bash
python -m training.data_build.extract_teacher_corpus \
  --source-dir data/teachers/sql101/original \
  --course-id sql101 \
  --out data/teachers/sql101/extracted/blocks.jsonl
```

Generate teacher-stage JSONL with model-assisted generation:

```bash
python -m training.data_build.generate_teacher_jsonl \
  --extracted-file data/teachers/sql101/extracted/blocks.jsonl \
  --train-out data/teachers/sql101/processed/train.jsonl \
  --eval-out data/teachers/sql101/processed/eval.jsonl \
  --model-path models/granite-3.3-8b-instruct
```

`--adapter-path` remains optional, but the default recommendation for teacher
JSONL generation is to use the base model first so the course-material-to-JSONL
step is not biased by the already adapted cybersecurity teaching style.

Validate output:

```bash
python -m training.data_build.validate_teacher_jsonl \
  --train-file data/teachers/sql101/processed/train.jsonl \
  --eval-file data/teachers/sql101/processed/eval.jsonl
```
