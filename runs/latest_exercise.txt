In this SQL security classroom exercise, students will explore the concept of SQL injection through unsafe dictionary expansion. They will learn how untrusted input can influence data access paths and query generation, even in a robust framework. The exercise will involve a fictional internal HR analytics web application written in server-side Python, which constructs queries using user-provided parameters. Students will see how internal control keys, if exposed to the query construction path, can be exploited to alter the intended conjunction of conditions, potentially bypassing access controls and exposing sensitive employee data. Through this practice, students will reinforce the design principle of treating all user input as untrusted and constructing queries through safe parameterization and strict whitelisting. They will also apply a safer design that eliminates unvalidated user influence over the query plan and verify that the vulnerability is no longer present. This exercise aligns with the course topic of secure data access and query integrity, emphasizing the importance of validating, whitelisting, and separating input handling from query construction to maintain deterministic and auditable access controls.

assistant SQL injection through unsafe dictionary expansion occurs when an attacker is able to influence the way a database query is constructed by supplying untrusted input that is directly incorporated into the query. Imagine a web application that allows users to filter data by entering values into search fields. If the application directly includes these search fields into the SQL query without proper validation, an attacker could insert malicious code or manipulate internal control parameters (like logical connectors) to change how the query works. For example, an attacker might try to change a default 'AND' condition to an 'OR' condition, which could lead to unauthorized data exposure. This highlights the importance of using safe query construction methods, such as parameterized queries, and ensuring that only trusted input is used to build database queries.
